2026-10-01  Resonator dataclass; corrected frequency shift; tests, README and
            notebooks on the new API
--------------------------------------------------------------------------
(uncommitted)

Physics (formulas provided by the user):
  g_n = c e (E . x_n) / (2 sqrt(m_e C)),   c = sqrt(2) for the differential mode
  chi_e(w) = sum_n 4 g_n^2 / (w_n^2 - w^2 + 2 i w Gamma_n)
  2 pi delta_f = -w_r Re{chi_e(w_r) / 2}
In Hz: g_n/2pi, gamma_n = Gamma_n/2pi, chi_e(f) = sum 4 g^2/(f_n^2 - f^2 + 2i f gamma_n).

1. New module src/quantum_electron/resonator.py: Resonator (frozen dataclass)
   - frequency [Hz], capacitance [F], mode ('diff' | 'single', required, no
     default), electrodes (RF electrodes: (plus, minus) or (signal,)).
   - capacitance for 'diff' is C_d = capacitance of each node to ground plus
     twice the capacitance between the nodes (Ca + 2 Cdot in the symmetric
     coupled LC model); for 'single' the LC capacitance.
   - mode_factor: sqrt(2) for 'diff', 1 for 'single'. Validates mode,
     positive values, number of electrodes. Exported from quantum_electron.

2. FullModel (src/quantum_electron/full_model.py)
   - get_coupling_to_mode(mode_id, resonator) [Hz]: g_n with the sqrt(2) from
     the resonator mode (was hard-coded). Vectorized field evaluation.
     Raises ValueError if the eigenvectors contain the cavity coordinate
     (compute_spectrum(resonator_dict=...)), instead of a shape error.
   - New get_susceptibility(resonator, gamma_e, frequency=None): complex
     chi_e, at f_r or on an array of frequencies; gamma_e scalar or per mode.
   - get_frequency_shift(resonator, gamma_e) and
     get_frequency_shift_from_single_mode(mode_id, resonator, gamma_e):
     delta_f = -f_r Re{chi_e(f_r)}/2. FIXED SIGN (was +). The damping enters
     as 2 i f_r gamma_e (was a real term, so np.real() had no effect).
   - The RF field is set from resonator.electrodes (set_rf_interpolator is
     only re-run when the electrodes change; set_rf_interpolator now
     records them in self.rf_electrode_labels and no longer modifies the
     list passed to it).
   - Mode frequencies that are nan (zero modes, unstable configuration) are
     treated as 0 Hz with a QuantumElectronWarning (they made the total nan).
   - find_ground_configuration raises ValueError when there is no initial
     condition (instead of failing inside scipy).
   - plot_electron_positions raises ValueError for an unknown state (printed
     a message, then raised UnboundLocalError).

3. EOMSolver.setup_eom (src/quantum_electron/eom_solver.py)
   - Without a resonator, the cavity-electron terms (which need the RF field)
     are skipped; they were computed and then cropped. Same result, but
     compute_spectrum() no longer requires set_rf_interpolator.

Verification against the exact models of the package (tests/test_resonator.py):
   - Differential: setup_eom_coupled_lc(mode='diff'), Ca = Cb, 1 and 2
     electrons, Cdot = 1e-17 and 1e-15 F: get_frequency_shift with
     C_d = Ca + 2 Cdot agrees within 2e-3 (ratio 1.000), and is negative.
     Before: ratio -1 (sign) at small Cdot, drifting by 2 Cdot/C.
   - Single-ended: setup_eom + get_cavity_frequency_shift, f_r = 5 GHz
     (below the electron modes: negative) and 20 GHz (above: positive).
   - sqrt(2) between 'diff' and 'single'; susceptibility (real part = shift,
     Im < 0 with damping, sum of single modes, frequency arrays, per-mode
     gamma); RF field from electrodes; error cases.

4. Tests migrated to the stateful API
   - tests/helpers.py: ring_initial_condition (the deterministic ring of
     radius 0.18 um around the minimum that get_electron_positions used by
     default) and solve(); existing tests keep testing the same thing.
   - test_warnings: minimize is patched in quantum_electron.full_model (the
     refactor imports it directly); the n_electrons mismatch test is
     replaced by a test for the missing-initial-condition error.
   - test_initial_condition: radius_um test replaced by a test of the new
     generate_initial_condition (box, min_dist, results, seed).

5. README and notebooks
   - README: Getting started shows generate_initial_condition ->
     find_ground_configuration -> results, and the Resonator / coupling /
     susceptibility / shift workflow with the formulas; Units and Warnings
     sections updated.
   - Notebooks 00-06: get_electron_positions(...) ->
     find_ground_configuration(...) + res = fm.results.minimization_results;
     plot_electron_positions(res, ...) -> plot_electron_positions("final", ...).
     Calls that relied on the old default ring now call
     generate_initial_condition(n, box=Point(minimum).buffer(0.2),
     min_dist=0.01, rng=0): random (seeded) positions in a disk of radius
     0.2 um around the potential minimum. Explicit initial conditions are

2026-09-30  Warnings instead of printed messages
--------------------------------------------------------------------------
(uncommitted)

1. New module src/quantum_electron/exceptions.py
   - QuantumElectronWarning(UserWarning): base class for the package.
   - ConvergenceWarning(QuantumElectronWarning): minimization did not
     converge.
   - Both exported from quantum_electron. Filter with the warnings module,
     e.g. warnings.simplefilter("ignore", QuantumElectronWarning) or
     warnings.simplefilter("error", ConvergenceWarning).

2. Problem reports now use warnings.warn (stacklevel points at the caller)
   - FullModel.get_electron_positions: initial condition does not match
     n_electrons; unbound electrons removed; electrons outside the domain
     (one warning listing all coordinates); initial minimization did not
     converge (ConvergenceWarning, now includes scipy's message).
   - InitialCondition.make_by_chemical_potential: could not fit all
     electrons.
   - suppress_warnings keeps working (no warnings issued); docstring updated.
   - Progress output behind verbose / do_print (convergence monitor,
     annealing messages) and package_versions() are still printed.
     "Restart minimization!" is now printed only with verbose=True.

3. Bugs fixed along the way (all in get_electron_positions unless noted)
   - With suppress_warnings=True and remove_unbound_electrons=True, the
     minimization was never restarted after removing unbound electrons:
     the removal message and the restart decision shared one `if`, so
     silencing messages changed the result. Confirmed on the previous code
     (minimize called with [3] electrons instead of [3, 2]).
   - verbose=True printed "SUCCESS: Initial minimization for Trap
     converged!" even when it had not converged.
   - The reported "L-inf norm of gradient" was np.amax(jac), ignoring large
     negative components; now np.max(np.abs(jac)).
   - no_electrons_left is initialized before the loop (it was only defined
     inside it; worked only via short-circuit evaluation).
   - EOMSolver.setup_eom_coupled_lc: an unknown resonator_dict['mode'] only
     printed a message and continued, leaving self.f0 unset or stale from a
     previous call, so get_cavity_frequency_shift could silently return a
     wrong shift. Now raises ValueError before any computation.

4. README: new "Warnings" section.

5. Tests: tests/test_warnings.py (new)
   - ConvergenceWarning (forced with a 1-iteration minimizer), silenced by
     suppress_warnings, turned into an error by a filter.
   - Initial condition / n_electrons mismatch; could not fit all electrons.
   - Unbound removal restarts the minimization independent of
     suppress_warnings (deterministic fake minimizer, counts the calls).
   - Invalid resonator mode raises ValueError.

2026-09-30  InitialCondition.random_particles
--------------------------------------------------------------------------
(uncommitted)

1. New method InitialCondition.random_particles(polygon, n, min_dist,
   rng=None, max_tries=100_000, keep_off_boundary=False)
   Files: quantum_electron/initial_condition.py
   - Places n electrons at random inside a shapely polygon, with every pair
     at least min_dist apart (rejection sampling). keep_off_boundary=True
     also keeps electrons >= min_dist/2 from the polygon edge. rng accepts a
     seed or a numpy Generator for reproducible initial conditions.
   - Algorithm as provided by the user; adapted to the conventions of the
     other make_* methods: polygon and min_dist in microns, returns
     [x0, y0, x1, y1, ...] in meters, ready for get_electron_positions.
   - Raises ValueError if the (buffered) polygon is empty, RuntimeError if
     fewer than n electrons fit within max_tries trial points.

   - Non-convex L-shaped polygon: count, containment, edge distance with
     keep_off_boundary, pairwise spacing >= min_dist, reproducibility.
   - Both error cases.

2026-09-30  FullModel accepts CouplingConstants; FreeFem 2Dmap reader
--------------------------------------------------------------------------
(uncommitted)

1. New module quantum_electron/coupling_constants.py
   - CouplingConstants: dataclass (x, y, data) with the same fields and
     conventions as zeroheliumkit.fem.fieldreader.CouplingConstants:
     x, y in microns, data[electrode] indexed as [y, x], shape (ny, nx).
   - read_ff_output(filename, ff_type): parser for FreeFem '2Dmap' and
     '2Dslices' text output (as provided by the user), with ff_types and
     flatten defined alongside it.
   - load_coupling_constants(filename): reads a '2Dmap' file into a
     CouplingConstants. The file stores arrays indexed as [x, y] (checked on
     the non-square nat_comm_dot_zoomed_in.txt: 251 x-points, 501 y-points),
     so they are transposed to [y, x].
   - to_potential_dict(obj): converts a CouplingConstants (this package or
     zeroheliumkit; matched on the attributes x, y, data, so zeroheliumkit
     is not imported or required) into the internal potential_dict with
     arrays indexed as [x, y]. A dict is returned unchanged. Raises on
     masked arrays (splines cannot interpolate them; zeroheliumkit's
     make_masked produces these) and on arrays whose shape is not
     (len(y), len(x)).
   - Exported from quantum_electron: CouplingConstants,
     load_coupling_constants, to_potential_dict.

2. Constructors accept either a potential_dict or a CouplingConstants
   Files: quantum_electron/electron_counter.py (FullModel),
          quantum_electron/utils.py (PotentialVisualization, make_potential,

          (InitialCondition)

2026-09-30  EOM interaction prefactor, screening consistency, np.int crash
--------------------------------------------------------------------------
(committed as ebb4b75 on branch fix-eom-prefactors)

1. Fixed electron-electron stiffness prefactor in the equations of motion
   Files: quantum_electron/eom_solver.py (setup_eom, setup_eom_coupled_lc)
   - The Hessian of the pairwise interaction phi(r) = A/r is
     phi_xx = A/(2 r^3) * (1 + 3 cos 2theta); the 1/2 comes only from the
     double-angle identity. The 1/2 used in Vee to avoid double counting
     the energy cancels on differentiation (grad_Vee already uses 1).
   - Commit a856ff9 fixed this for the Coulomb branch of setup_eom only.
     The Yukawa branch of setup_eom and both branches of
     setup_eom_coupled_lc still used 1/4, halving the interaction stiffness.
   - Impact: mode frequencies / cavity shifts computed with screening on,
     or with the coupled-LC model, were wrong. Symptoms for 2 electrons in
     a parabolic trap: rotation mode at 0.707 f_com instead of 0, breathing
     mode at sqrt(2) f_com instead of sqrt(3) f_com.

2. Coulomb vs. Yukawa choice in the EOM now also honours include_screening
   Files: quantum_electron/eom_solver.py
   - Previously the EOM only checked screening_length == np.inf, while the
     position solver checks include_screening. With include_screening=False
     and a finite screening_length, positions used Coulomb but modes used
     Yukawa. Now: Coulomb if (not include_screening) or length is inf.

3. Fixed crash in parallel_perturb_and_solve on NumPy >= 1.24
   Files: quantum_electron/position_solver.py
   - np.int -> int in single_thread (np.int was removed from NumPy).
   - multiprocessing.Pool is now used as a context manager so it is closed.

4. Added regression tests
   Files: tests/test_eom.py (new)
   - Checks the analytic 2-electron spectrum (0, f_com, f_com,
     sqrt(3) f_com) for setup_eom and setup_eom_coupled_lc (Ltail = 0 and
     1 nH), for Coulomb and for Yukawa with a very long screening length.
